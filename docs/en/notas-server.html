    Server 16.1 RC 3

    Vega changes, schedule, limits and integrity of the Server candidate.

    Lyra OS Server 16.1 RC 3 “Delos” is the third and final release candidate of the Server on openSUSE Leap 16.1: a headless edition with a console installer and administration through Vega. RC 3 is the final candidate and is frozen: with no P0 or P1 issues, the same ISO is promoted to the stable 16.1 release (tag server-v16.1) on 2026-11-19, without a rebuild.

    What changed since RC 2

    The image, the installer and the functional limits are those of RC 2. What changes are the Vega packages and the way the system identity is written.

    • vegad 5.6.2: full health diagnostics (package integrity, disk health, logs, platform, security, boot time and network), with safe fixes for each finding; a weekly check (vegad-health-check.timer, enabled at installation) that runs the light tests at low priority and only warns about what is new; Free up space (core dumps, old journal, zypper cache, unused Flatpak, old kernels and Snapper cleanup). Over SSH, members of the wheel group read the weekly check result, the space measurement and the network test without a password, as in the local session.
    • vega-cli 5.2.0: on startup, it shows a summary of weekly check findings not yet seen; Hardware and Kernel → Health diagnostics (quick mode, single test, report, Fix, I've seen the logs and check frequency); Network and Firewall → My internet doesn't work; Storage → Free up space. The polkit password prompt appears on a clean screen and allows 5 minutes to type.
    • vega-web 5.2.0: Hardware and Kernel → Health diagnostics, with progress, a report with boot time by phase and the network step by step, Fix per finding, periodic check and the latest weekly check; Network and Firewall → My internet doesn't work, with a single password; Storage → Free up space, with cleanup progress; Ask for help from the report; and the periodic check status on the home dashboard.
    • System identity: Lyra's /etc/os-release is now a file of its own, as on the Desktop. It used to be written through the Leap-release package link: package diagnostics reported a modified program and Fix reinstalled Leap-release, bringing back the openSUSE identity.

    Scope and limits

    No new application or architecture change was added to the image. The edition remains headless, with UEFI whole-disk installation (GPT, EFI partition and ext4 root), an administrative account with sudo, a locked root account, SSH, firewalld and Vega (vegad, vega-cli and vega-web). RAID, LVM, Btrfs, Snapper, legacy BIOS, unattended installation and upgrades between releases remain outside the 16.1 scope.

    How the RC was qualified

    The full Server gate was repeated on the exact ISO, with vegad 5.6.2, vega-cli 5.2.0 and vega-web 5.2.0 in the package inventory. In addition to the items from the previous RCs, the gate checks over SSH the health diagnostics, the weekly check summary, the network test and Free up space in vega-cli, the same functions in vega-web through the browser, and that the diagnostics package test no longer offers to reinstall Leap-release on the installed system. Testing on physical hardware remains a declared risk.

    Known issue

    An update of the Leap-release package itself can still replace the system identity with openSUSE's. The issue has P3 priority and is tracked in issue #38.

    Integrity

    The published bundle includes the ISO, the package inventory, the KIWI verification, CycloneDX and SPDX SBOMs, the checksum and the detached signature. Check them:

    sha256sum -c LyraOS-Server-16.1-rc.3-x86_64.iso.sha256
gpg --verify LyraOS-Server-16.1-rc.3-x86_64.iso.sha256.asc LyraOS-Server-16.1-rc.3-x86_64.iso.sha256

    The signature must be valid for the official release key, fingerprint 01B6 3EED BE6B 0791 26A0 116E FA73 53A1 31EC EFEB. Installation is described in Install the Server.

    Lyra OS Server

    Install the server edition and start managing it from the console with Vega CLI.

    An edition for service administration

    Lyra OS Server is an edition without a graphical environment. It is administered through the console, Vega CLI and Vega Web. The 1.1 Beta 1.1 candidate uses the openSUSE Leap 16.1 base and keeps the functional scope of Beta 1.

    Storage in the Server 1.1 series: whole-disk UEFI installation, with GPT, an EFI partition and an ext4 root. RAID, LVM, Btrfs, Snapper, legacy BIOS and unattended installation are outside the documented flow for this candidate.

    Install the Server

    1. Check the requirements, prepare a dedicated disk and back up. The contents of the chosen disk will be erased.
    2. Download the Server image from the downloads section and verify the integrity files from the same release.
    3. Write the ISO and boot in UEFI mode. The installer is interactive and runs in the console.
    4. Enter the language, keyboard, time zone, hostname and account details requested.
    5. Review the chosen disk and confirm the installation only after checking the summary.
    6. When it finishes, restart from the installed disk and log in with the account you created.

    Prepare Ethernet with DHCP for the initial setup. Network adjustments, such as a static address, are made after installation.

    Manage with Vega CLI

    On a local interactive console or in an already configured SSH session, run as your user:

    vega

    Use the menus to check the system state and manage the available functions. Authentication is requested for each privileged operation.

    Check the first boot

    These commands query the system state without changing the configuration:

    cat /etc/os-release
ip -brief address
systemctl --failed

    Check the installed version, the address received by the network interface and any failed services. The initial policy described by the project allows SSH and Vega Web on port 9090/tcp; confirm the actual state of the firewall and services on your installation before remote access.

    Vega Web is intended for administration on the local network. See its documentation to configure HTTPS access and authentication: Vega Web guide.

    Keep a recovery copy

    Plan backups of the data and of the service configurations. This edition does not offer Snapper rollback or automatic downgrade of an installation on the new base. See updates and troubleshooting.

    Desktop 16.1 RC 2

    What is new, limits, qualification and integrity of the GNOME Desktop candidate.

    Release notesDesktop GNOME · 16.1 RC 2Documentation review: Oct 28, 2026Translated from the Portuguese version reviewed on Oct 28, 2026

    Lyra OS Desktop 16.1 RC 2 “Odisseia” is the second release candidate of the GNOME Desktop on openSUSE Leap 16.1. It gathers the fixes found after RC 1 and brings basic parental controls. Apart from that exception, approved by the maintainer, the strict freeze still applies: until the stable release, only fixes for bugs, crashes, security and critical performance are accepted.

    Because the image content changed, RC 2 is a new candidate and went through the full gate again. RC 1 remains listed as history.

    Changes since RC 1

    • Basic parental controls: create a supervised account on the Users page of Vega and set the rules in the GNOME Parental Controls app: browsers, applications, software installation and age rating. The supervised account cannot administer the system, cannot log in through a TTY or SSH, cannot use Alt+F2 and does not see the terminals or Vega; the Sheliak menus and search follow the rules. See the parental controls guide.
    • sudo security: only accounts in the wheel group can use sudo, with their own password. Previously, the installer let any account become root with its own password. Existing installations receive the fix through the normal update.
    • Vega 5.3.2: the Vega interface was rebuilt with Tauri, with the same features as the GTK version.
    • Firewall in Vega: the status shows the zone that actually filters the traffic (public), no longer the docker zone or an empty zone. The firewall rules did not change; only the display was wrong.
    • Bluetooth without an adapter: on machines without Bluetooth, Vega immediately shows “No Bluetooth adapter found” instead of loading for a minute and ending in an error, and the service no longer shows up as a failure on the Dashboard.
    • “Update all”: Vega no longer leaves behind updates that depend on a new package from another repository.
    • Network names with accents: connection names with accented characters, such as the Portuguese “Conexão cabeada 1”, are shown correctly in Vega, and setting a static IP on them works again.
    • Live session: the screen no longer locks after a few idle minutes; before, anyone who stepped away during the installation lost the session, because the live account has no password. The installed system keeps the default GNOME lock.
    • Power profiles: the GNOME power profile selector is back, provided by tuned-ppd.
    • Graphics and hybrid laptops: the image includes the Intel and AMD Vulkan drivers, and GTK 4 now renders on the integrated GPU. When the NVIDIA driver is installed through Vega on a hybrid laptop, the NVIDIA GPU powers off when idle (RTD3), which saves battery.
    • Flatpak and LinuxToys: no longer preinstalled. Flatpak, with Flathub, is enabled on the Software page of Vega, which warns you when there are supervised accounts. LinuxToys remains available in the Lyra repository. Existing installations keep what they already have.
    • On the first update: vegad 5.1.47 arrives through zypper or Vega and asks for the administrator password only once for a queue of Flatpaks, instead of once per application.

    Scope and limits

    • New installations only. If you already use RC 1, you receive Vega, vegad, the sudo fix and parental controls through the normal update, without reinstalling. The other image changes (power profiles, Vulkan drivers, Flatpak and LinuxToys out of the default installation) do not arrive through updates.
    • Parental controls are basic: they do not filter websites and do not withstand a tech-savvy child. With Flatpak enabled, the supervised account can install and open Flatpak applications.
    • GNOME is the only Desktop edition; the KDE Plasma and XFCE editions were discontinued.
    • RAID, LVM, manual partitioning and side-by-side installation remain outside the covered scenario.
    • System languages: en-US, pt-BR and es-ES, with English as the fallback.

    How the RC was qualified

    The exact ISO went through the release gate again in a QEMU/KVM virtual machine: live session with and without network, UEFI installation with Secure Boot, legacy BIOS and UEFI without EFI variables, first boot, update with snapshot rollback, languages and a check of the OBS repositories. On the installed system, the firewall zone in Vega, the power profile selector, the sudo policy and parental controls were also checked. Every item passed, and the GO decision is published with the release.

    Known issue: in the live session, installing software through Vega asks for a password the live account does not have, and the installation does not happen. The Lyra installer and the installed system are not affected; the fix goes into the stable release. Risks: qualification was done in a virtual machine, and validation on physical hardware is still in progress; with NVIDIA cards, an external monitor may not wake up after suspend.

    Integrity

    Download the ISO, the .sha256 file and the .sha256.asc signature from the same folder and check them:

    sha256sum -c LyraOS-Desktop-16.1-rc.2-x86_64.iso.sha256
gpg --verify LyraOS-Desktop-16.1-rc.2-x86_64.iso.sha256.asc LyraOS-Desktop-16.1-rc.2-x86_64.iso.sha256

    The signature must be valid for the official release key, the same as RC 1, fingerprint 01B6 3EED BE6B 0791 26A0 116E FA73 53A1 31EC EFEB. The step-by-step procedure is in the installation guide.

    Stable release

    The stable 16.1 release will be rebuilt from the final openSUSE Leap 16.1 packages, released on November 3, 2026, with the same Lyra content as RC 2, and will go through a new gate before publication, planned for November 5, 2026, with November 26 as the limit.

    Source: release notes in the Desktop repository (in Portuguese).

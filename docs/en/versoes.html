    Versions and support

    Understand Alpha, Beta, RC, Lyra's version numbers and how they relate to the openSUSE base.

    Lyra has its own version numbers

    The project uses the MAJOR.MINOR.PATCH format: a product generation, a compatible evolution within that generation and a maintenance revision. The 1.1 line is in development.

    The openSUSE Leap base is identified separately. A change of base does not automatically determine the Lyra OS version number.

    Alpha, Beta and RC

    • Alpha: development candidate for testing integration and finding problems.
    • Beta: validation and stabilization stage, still before the final release.
    • RC: release candidate, subject to approval against the quality criteria.

    Identifiers such as 1.1-alpha.7 and 1.1-beta.1.1 distinguish the candidates. Desktop and Server have independent cycles. Moving to the next stage depends on testing and on resolving blockers, not just on a date.

    Check the notes for your image

    Always consult the release that corresponds to the file you downloaded. These are the documents for the images referenced in this edition of the guides:

    • Desktop 1.1 Alpha 7: move of the base to Leap 16.1 and installation and upgrade limits.
    • Server 1.1 Beta 1.1: base revision preserving the scope of Beta 1.

    Community support

    Lyra OS is an independent project and version 1.1 will have community support. No contractual timeframe or end-of-support date is promised without a formal policy. Support for the openSUSE base and the cycle of a Lyra version are separate matters.

    To ask for help, describe the version and the situation following the problem reporting guide. For details of the policy maintained on the website, see the versioning document (in Portuguese).

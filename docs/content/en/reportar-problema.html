Before opening

  • Update the system with sudo zypper up or from Vega, in Software. The defect may already be fixed.
  • Search the repository issues for a similar report. If you find one, add your information in a comment instead of opening another.
  • Usage questions go to the questions and answers forum, not to the issues.

Where to open

  • Desktop: installation, boot, the desktop and the system in general.
  • Server: the server edition.
  • Defects in an app go to its own repository, such as Vega.

When in doubt, open it in the repository of the edition you use. The team moves the issue if needed.

What to include

  1. The system version, shown by this command:
    grep PRETTY /etc/os-release
  2. The steps to reproduce the problem.
  3. What you expected to happen.
  4. What actually happened, with the exact error message.
  5. Screenshots or logs, when they help. See how to collect them in Gather system information.

With Vega

On the Desktop, the Ask for help button in the Vega diagnostics puts together a text with the versions and the test results, already without personal data. Paste that text into the issue. See Ask for help.

Security flaws

Never report a vulnerability in a public issue. Use the private vulnerability report and read the security policy.

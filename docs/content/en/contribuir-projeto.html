Ways to help

  • Questions and answers: ask and answer in the questions and answers forum. A good question, with the version and the steps, helps whoever comes next.
  • Bug reports: see How to report a problem.
  • Translations: pull requests to the po/ folder of the app repositories or to the website repository. See Translate and update translations.
  • Code: fixes and improvements in the project repositories. The ecosystem map shows what each one does.

Principles

  • Stability first.
  • Reuse openSUSE instead of reinventing it.
  • Tools that help people act: fix the problem, find the shortcut or know what to do.
  • Big changes go through an OpenSpec specification first, discussed before the code.

How to submit code

  1. Read the repository's README.md and, when there is one, its AGENTS.md.
  2. Create a branch and open a pull request to main.
  3. Keep the pull request small and focused on a single subject.
  4. Write texts and commit messages in Portuguese.
  5. CI must pass before the merge.

In the stable release

During the stable 16.1, only fixes go in: defects, crashes, security and critical performance problems.

Modi per aiutare

  • Domande e risposte: chiedi e rispondi nel forum di domande e risposte. Una buona domanda, con la versione e i passaggi, aiuta chi arriva dopo.
  • Segnalazioni di difetti: vedi Come segnalare un problema.
  • Traduzioni: pull request nella cartella po/ dei repository delle applicazioni o nel repository del sito. Vedi Traduci e aggiorna le traduzioni.
  • Codice: correzioni e miglioramenti nei repository del progetto. La mappa dell'ecosistema mostra cosa fa ciascuno.

Principi

  • Prima di tutto la stabilità.
  • Riutilizzare openSUSE invece di reinventarlo.
  • Strumenti che aiutino le persone ad agire: correggere il problema, trovare la scorciatoia o sapere cosa fare.
  • Le modifiche grandi passano prima da una specifica OpenSpec, discussa prima del codice.

Come inviare codice

  1. Leggi il README.md del repository e, quando esiste, il suo AGENTS.md.
  2. Crea un branch e apri una pull request verso main.
  3. Mantieni la pull request piccola e concentrata su un solo argomento.
  4. Scrivi i testi e i messaggi di commit in portoghese.
  5. La CI deve passare prima del merge.

Nella versione stabile

Durante la 16.1 stabile entrano solo correzioni: difetti, crash, sicurezza e problemi critici di prestazioni.

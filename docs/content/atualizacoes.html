Instale aplicativos pelo Vega

Abra o Vega e acesse a área de software. Pesquise o aplicativo, confira sua origem e revise a operação antes de confirmar. O Vega oferece gerenciamento de pacotes RPM via Zypper e de aplicativos Flatpak quando esse suporte está disponível.

RPMs fazem parte do sistema de pacotes da distribuição. Flatpaks usam seus próprios repositórios e runtimes. Um mesmo aplicativo pode aparecer em mais de uma origem; escolha a que pretende manter para evitar instalações duplicadas.

Atualize o sistema instalado

  1. Conecte o computador à rede e à alimentação elétrica.
  2. Abra a área de atualizações do Vega e atualize a lista disponível.
  3. Leia o resumo e confirme as alterações desejadas.
  4. Aguarde o resultado. Reinicie se a ferramenta solicitar ou se uma atualização precisar de um novo boot para entrar em uso.

Se optar pelo terminal, o fluxo de atualização dos pacotes RPM é:

sudo zypper refresh
sudo zypper update

O primeiro comando atualiza os metadados dos repositórios; o segundo apresenta as atualizações para confirmação. Eles não atualizam aplicativos Flatpak. Não execute ao mesmo tempo outra operação de pacotes pelo Vega.

Cuide das origens dos pacotes

Mantenha os repositórios adequados à base da sua instalação. Não adicione repositórios de outra versão do Leap para obter um pacote isolado. Se aparecer uma chave desconhecida ou mudança inesperada de origem, confira a publicação do projeto antes de aceitar.

Atualização não é migração de versão

Trocar a base exige um procedimento específico. Atualizar pacotes não autoriza migrar entre versões do openSUSE Leap ou entre candidatas do Lyra. Aguarde um caminho de migração documentado para sua origem e destino.

As notas da Alpha 7 registram que a migração de instalações existentes da base Leap 16.0 para 16.1 depende de validação específica. Não altere os endereços dos repositórios nem use uma atualização de distribuição como atalho.

Backup e recuperação

Guarde seus arquivos importantes em outro dispositivo antes de alterações grandes. Snapshots, quando configurados, ajudam na recuperação do sistema, mas não substituem uma cópia independente dos dados. O Server 1.1 usa ext4 e não oferece o fluxo de rollback com Snapper do Desktop.
